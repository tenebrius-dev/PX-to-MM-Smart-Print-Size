# План построения canvas-overlay для PX to MM — Smart Print Size

Статус: реализация включена в v1.4.0. Автоматические проверки пройдены; ручная проверка в Figma Desktop для Layers, Undo, экспорта и multiplayer остаётся отдельным gate.

## Ключевое ограничение

Figma не предоставляет Plugin API для изменения нативной синей рамки выделения. Поэтому оверлей можно построить только как временную canvas-ноду поверх документа. `figma.showUI()` создаёт отдельное iframe-окно, а не слой внутри редактора.

Источники:

- [Figma showUI](https://developers.figma.com/docs/plugins/api/properties/figma-showui/)
- [Figma selection API](https://developers.figma.com/docs/plugins/api/properties/PageNode-selection/)
- [Figma Plugin API: событие close](https://developers.figma.com/docs/plugins/api/properties/figma-on/)

Это означает, что нативная внутренняя синяя рамка останется видимой. Дополнительная рамка появится снаружи неё, когда учитывается внешняя часть Stroke.

## Принцип минимальной реализации

Реализация должна быть экономичной: менять только код, который необходим для этой feature, и переиспользовать существующие расчёты, refresh-механику, типы сообщений и UI-контролы.

Не добавлять новые зависимости, отдельный режим панели, новый визуальный контрол, параллельную систему обновления или несвязанный рефакторинг. Любое новое состояние, событие или модуль добавлять только при наличии прямой связи с жизненным циклом оверлея. Если требование можно выполнить существующей функцией, не создавать вторую реализацию.

## 1. Предварительный технический прототип

Сначала создать минимальную временную рамку вокруг одного прямоугольника и проверить:

- остаётся ли исходный объект единственным выделенным;
- не мешает ли заблокированная рамка кликам;
- попадает ли создание и удаление рамки в Undo;
- видна ли рамка другим участникам файла;
- не попадает ли она в экспорт;
- как она ведёт себя при изменении zoom;
- удаляется ли она при закрытии плагина.

Figma отдельно указывает, что плагины могут создавать UI-элементы на canvas как ноды и должны удалять их в обработчике `close`.

Если прототип загрязняет Undo, Layers или экспорт, постоянный автоматический режим не выпускать: потребуется явный пользовательский Preview-toggle.

## 2. Поведение оверлея

Оверлей показывается только когда:

- выделен ровно один объект;
- выбран режим `Included`;
- Stroke видимый;
- Stroke размещён по центру или снаружи;
- внешнее расширение больше нуля;
- толщина и позиция Stroke определены однозначно.

Оверлей удаляется, если:

- выбран `Excluded`;
- Stroke выключен, удалён или равен нулю;
- Stroke находится внутри объекта;
- выделение пустое или множественное;
- объект или страница изменились;
- плагин закрывается.

Для `Inside Stroke` оверлей не нужен: нативная синяя рамка уже соответствует итоговым габаритам.

## 3. Расчёт геометрии

Текущий расчёт хранит суммарное расширение ширины и высоты. Для оверлея добавить четыре отдельных значения:

```text
leftOutset
rightOutset
topOutset
bottomOutset
```

Правила:

- `INSIDE`: везде `0`;
- `CENTER`: половина соответствующей толщины;
- `OUTSIDE`: полная соответствующая толщина;
- скрытый Paint: `0`;
- индивидуальные Stroke: отдельный расчёт каждой стороны;
- `figma.mixed` или неизвестная геометрия: оверлей не показывать.

Размер рамки:

```text
overlayWidth  = node.width  + leftOutset + rightOutset
overlayHeight = node.height + topOutset  + bottomOutset
```

Положение рамки сдвигается влево и вверх на `leftOutset` и `topOutset`.

`absoluteRenderBounds` не использовать как основной источник: он включает не только Stroke, но и тени и другие эффекты. [Документация по границам ноды](https://developers.figma.com/docs/plugins/api/node-properties/)

## 4. Повороты и вложенность

Оверлей создаётся верхнеуровневой нодой на текущей странице, чтобы он:

- не попадал под `Clip Content`;
- не становился ребёнком Auto Layout;
- не менял размеры родительских групп;
- всегда находился поверх выбранного объекта.

Для повёрнутых объектов оверлей получает тот же `absoluteTransform`, но его начало корректируется на `leftOutset` и `topOutset`. Рамка будет поворачиваться вместе с объектом.

Для групп, компонентов, инстансов, растра и обычных прямоугольных объектов используется прямоугольник геометрических границ с добавленным Stroke-outset.

Для сложных векторов, линий, переменной толщины и неизвестных случаев используется безопасный fallback: оверлей не создаётся, если точная граница не может быть вычислена без расхождения с расчётом панели.

## 5. Контроллер оверлея

Создать отдельный модуль:

`src/plugin/overlay-controller.ts`

Основные операции:

```text
showOverlay(target, strokeOutsets)
updateOverlay(target, strokeOutsets)
removeOverlay()
cleanupStaleOverlays()
isOverlayNode(node)
```

Состояние контроллера:

```text
targetNodeId
overlayNodeId
pageId
lastZoom
includesOutsideStroke
```

Сама рамка:

- `RectangleNode` без Fill;
- контрастный зелёный Stroke, чтобы отличать guide от нативной синей рамки Figma;
- заблокирована;
- не входит в selection;
- находится сверху страницы;
- имеет служебное имя;
- помечена через `setPluginData`;
- не участвует в расчётах размеров.

## 6. Синхронизация

Контроллер подключить к существующим событиям:

- `selectionchange`;
- `currentpagechange`;
- `PageNode.nodechange`;
- изменение `Included / Excluded`;
- изменение Stroke;
- resize и scale из плагина;
- `figma.on('close')`.

Собственные изменения оверлея фильтровать по `pluginData`, чтобы обновление рамки не запускало бесконечную цепочку `nodechange`.

Существующий debounce 24 мс использовать и для геометрии, и для оверлея.

## 7. Связь с Included / Excluded

Сейчас `Included / Excluded` хранится локально в React. Потребуется сообщение из UI в main-код:

```text
set-stroke-inclusion-preview
```

Поведение:

- `Included` — создать или обновить внешнюю рамку;
- `Excluded` — немедленно удалить рамку;
- смена `mm / px` — рамку не менять, поскольку геометрия объекта не изменилась.

Новых визуальных контролов в панели не добавлять, чтобы сохранить текущую высоту и UI3-композицию.

## 8. Толщина линии при изменении zoom

Canvas-Stroke масштабируется вместе с холстом. Чтобы линия выглядела как нативная однопиксельная рамка:

```text
strokeWeight = 1 / figma.viewport.zoom
```

Для Figma Design нет отдельного события изменения zoom, поэтому потребуется небольшой монитор только при активном оверлее:

- проверка примерно каждые 100–150 мс;
- обновление только при фактическом изменении zoom;
- остановка после удаления рамки или закрытия плагина.

Цвет и визуальную толщину откалибровать по Figma Desktop в Light и Dark. Точное совпадение с закрытой системой Figma заявлять только после реального визуального smoke-теста.

## 9. Очистка и аварийное восстановление

- При нормальном закрытии рамка удаляется синхронно.
- При запуске плагин ищет на текущей странице ноды со своим `pluginData` и удаляет оставшиеся.
- При переходе на другую страницу старая рамка удаляется до создания новой.
- При аварийном завершении рамка может временно остаться в документе; полностью исключить это ограничение Figma API нельзя.
- Служебное имя рамки должно явно указывать на Smart Print Size.
- Не выполнять асинхронные операции в обработчике `close`.

## 10. Тестирование

### Автоматические тесты

- Inside, Center и Outside;
- индивидуальные толщины четырёх сторон;
- выключенный и нулевой Stroke;
- `figma.mixed`;
- повороты 0°, 90° и произвольный угол;
- вложенность во Frame, Group и Auto Layout;
- исключение оверлея из selection и расчётов;
- отсутствие рекурсивного `nodechange`;
- удаление при смене страницы и закрытии;
- переключение `Included / Excluded`;
- восстановление после оставшейся служебной ноды.

### Ручная проверка в Figma

- Frame, Group, Rectangle, Vector, Text и растр;
- zoom 25%, 100%, 200% и 400%;
- Light и Dark;
- resize и scale в реальном времени;
- экспорт выбранного объекта;
- Undo/Redo;
- Layers и multiplayer.

## Критерии готовности

Оверлей считается готовым, если:

- его границы совпадают с размерами Smart Print Size с погрешностью не более 0,5 экранного пикселя;
- выделение исходного объекта не меняется;
- обновление происходит без заметной задержки;
- скрытый Stroke не создаёт рамку и не участвует в расчёте;
- `Included / Excluded` обновляет рамку сразу;
- после закрытия не остаются служебные ноды;
- нет рекурсивных обновлений и заметного загрязнения Undo.

Неустранимое ограничение: нативную синюю рамку Figma нельзя заменить или скрыть через Plugin API. Поэтому внешний оверлей всегда будет дополнительной линией поверх нативного выделения.
